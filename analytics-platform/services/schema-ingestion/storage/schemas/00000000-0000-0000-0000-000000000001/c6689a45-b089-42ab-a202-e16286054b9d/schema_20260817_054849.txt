This table, named ‘categories’, is designed to store information about product categories. It contains the following columns:

*   category_id: A unique numerical identifier for each category, which cannot be empty. This is the primary key for the table.
*   category_name: The name of the category, which cannot be empty.
*   parent_category_id: A numerical identifier referencing another category in the same table, representing a parent-child relationship between categories. This column can be empty if a category is not a parent.

The table is named “customers” and is designed to store information about customers. It contains the following columns:

customer_id: A unique, large integer that serves as the primary identifier for each customer and cannot be empty.
first_name: The customer’s first name, which is required.
last_name: The customer’s last name, which is required.
email: The customer’s email address, which is required.
city: The customer’s city, which is required.
state: The customer’s state, which is required.
country: The customer’s country, which is required.
signup_date: The date when the customer signed up, which is required.
customer_segment: A categorization of the customer, which is required.

The inventory_movements table tracks changes in a product’s stock levels. 

It contains the following columns:
movement_id: A unique, automatically generated numerical identifier for each movement, which cannot be empty.
product_id: A unique numerical identifier for the product involved in the movement, which cannot be empty.
movement_date: The date and time when the movement occurred, and this cannot be empty.
movement_type: A text description of the type of movement (e.g., ‘sale’, ‘purchase’, ‘adjustment’), which cannot be empty.
quantity: The number of units involved in the movement, which cannot be empty.
reference_id: An optional numerical identifier referencing another table, such as an order or invoice.

The `order_items` table stores information about individual items within customer orders. 

Each record in the table represents a single line item on an order. The table includes the following columns:

*   `order_item_id`: A unique, automatically generated numerical identifier for each order item, which cannot be empty.
*   `order_id`: A unique numerical identifier for the order to which this item belongs, and cannot be empty.
*   `product_id`: A unique numerical identifier for the product included in the order item, and cannot be empty.
*   `quantity`: The number of units of the product included in the order item, and cannot be empty.
*   `unit_price`: The price of a single unit of the product at the time of the order, and cannot be empty.
*   `discount`:  A discount amount applied to the order item, and cannot be empty.

The `orders` table stores information about customer orders. Each order has a unique identifier, a customer ID, an order date, and a status. It also includes shipping details such as the destination city and state, the shipping fee, and information about any coupons applied. 

Here's a breakdown of the table's columns:

*   `order_id`: A unique, large integer that serves as the primary identifier for each order and cannot be left blank.
*   `customer_id`: A large integer that represents the customer who placed the order and cannot be left blank.
*   `order_date`: A timestamp that records the date and time the order was placed and cannot be left blank.
*   `order_status`: A text string describing the current status of the order and cannot be left blank.
*   `shipping_city`: A text string that specifies the destination city for the order and cannot be left blank.
*   `shipping_state`: A text string that specifies the destination state for the order and cannot be left blank.
*   `shipping_fee`: A numeric value representing the cost of shipping the order and cannot be left blank.
*   `coupon_code`: An optional text string that represents a coupon code used for the order.
*   `coupon_discount`: A numeric value representing the discount amount applied by the coupon code and cannot be left blank.

The table is named “payments” and is designed to store information about individual payments made in relation to orders.

Here’s a breakdown of the table’s columns:

payment_id: A unique, automatically generated numerical identifier for each payment, which cannot be left blank. It is the primary key for the table.
order_id: A unique numerical identifier for the order to which the payment is associated, and this cannot be left blank.
payment_date: The date and time when the payment was made, and this cannot be left blank.
payment_method: The type of payment method used (e.g., credit card, PayPal), and this cannot be left blank.
payment_status: The current status of the payment (e.g., pending, completed, failed), and this cannot be left blank.
amount: The monetary amount of the payment, stored as a number with a total of 12 digits, including 2 digits after the decimal point, and this cannot be left blank.
transaction_ref: A reference identifier for the transaction, which can be left blank.

The table is named ‘products’ and is designed to store information about individual products available for sale.
